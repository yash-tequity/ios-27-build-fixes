# iOS 27 and Xcode 27 build fixes for Expo / React Native apps

Last updated: 2026-10-30

Building an Expo app (prebuild / CNG) with Xcode 27 and the iOS 27 SDK breaks in three independent places. All three can be fixed on the Expo SDK the app already uses, with two config plugins and a patch-level dependency update. An Expo SDK upgrade is not required.

`ios/` is regenerated by `npx expo prebuild`, so every fix here is a config plugin or a dependency change. Never hand-edit `ios/` for these: the next prebuild silently drops the edit.

## At a glance

| # | Symptom | Cause | Fix |
|---|---------|-------|-----|
| 1 | The build fails on pod resource-bundle targets (SDWebImage, RNSVG, Sentry, AsyncStorage, react-native-device-info, lottie and similar) before any app code compiles | Xcode 27 turned an `IPHONEOS_DEPLOYMENT_TARGET` below iOS 15 from a warning into an error. CocoaPods stamps each resource bundle with the target from its own podspec, and `react_native_post_install` raises only the pod targets, never their bundles. | Config plugin that raises every pod target to the Podfile's own platform version |
| 2 | The app is killed at launch (`_UIApplicationEvaluateRuntimeIssueForNoSceneLifecycleAdoption`), or launches to a black screen | Apps built against the iOS 27 SDK must adopt the UIKit scene life cycle (UIScene) | Expo SDK 57.0.23+: `ios.enableSceneSupport`. Earlier SDKs: config plugin |
| 3 | Swift compile errors inside Expo native modules | The newer Swift compiler rejects code that older patch releases ship | Update to the newest patch release of your SDK line |

## Which fixes does your SDK need?

| Expo SDK | Fix 1: pod deployment target | Fix 2: UIScene | Fix 3: patch update |
|---|---|---|---|
| 58 and newer | Not verified. Keep the plugin until a prebuild shows no pod below iOS 15 | Built into the project template; nothing to add | Yes |
| 57.0.23 and newer | Plugin | `expo-build-properties` `ios.enableSceneSupport: true` | Yes |
| 53 to 56, and 57.0.0 to 57.0.22 | Plugin | Plugin (`with-ios-scene-lifecycle.js`) | Yes. SDK 56 needs `expo-modules-jsi` 56.0.13 or newer |
| 52 and older | Plugin | The scene plugin needs the Swift `ExpoReactNativeFactory` AppDelegate (SDK 53+). It throws on older templates; adapt it or upgrade | Yes |

## Fix 1: raise pod deployment targets

Create `plugins/with-ios-pod-deployment-target.js`:

```js
const fs = require('fs');
const path = require('path');
const { withDangerousMod } = require('@expo/config-plugins');

/**
 * Raises pod targets that sit below the project's iOS deployment target.
 *
 * `react_native_post_install` only raises the pods themselves, never the resource bundles
 * CocoaPods generates beside them, and a bundle keeps whatever its podspec declares - SDWebImage
 * still says iOS 9. Xcode 27 turned "below iOS 15" from a warning into an error, so those five
 * bundles fail the build before anything compiles.
 */

const POST_INSTALL = '  post_install do |installer|\n';
// A comment, kept separate from the Ruby variable below: conflating the two once turned the
// assignment into a comment and left the variable undefined at post_install time.
const MARKER = '# with-ios-pod-deployment-target';
const VAR = 'min_ios_version';

function patchPodfile(podfile) {
  if (podfile.includes(MARKER)) return podfile;

  const platform = podfile.match(/^platform :ios, (.+)$/m);
  if (!platform) {
    throw new Error('with-ios-pod-deployment-target: no `platform :ios,` line in the Podfile.');
  }
  if (!podfile.includes(POST_INSTALL)) {
    throw new Error('with-ios-pod-deployment-target: no `post_install do |installer|` block in the Podfile.');
  }

  // Same expression as the platform line, so the floor cannot drift from it.
  const block = [
    `    ${MARKER}`,
    `    ${VAR} = ${platform[1]}`,
    '    installer.pods_project.targets.each do |target|',
    '      target.build_configurations.each do |config|',
    "        deployment_target = config.build_settings['IPHONEOS_DEPLOYMENT_TARGET']",
    `        next if deployment_target.nil? || deployment_target.to_f >= ${VAR}.to_f`,
    `        config.build_settings['IPHONEOS_DEPLOYMENT_TARGET'] = ${VAR}`,
    '      end',
    '    end',
    '',
  ].join('\n');

  return podfile.replace(POST_INSTALL, `${POST_INSTALL}${block}\n`);
}

const withPodDeploymentTarget = (config) =>
  withDangerousMod(config, [
    'ios',
    (cfg) => {
      const podfile = path.join(cfg.modRequest.platformProjectRoot, 'Podfile');
      fs.writeFileSync(podfile, patchPodfile(fs.readFileSync(podfile, 'utf8')));
      return cfg;
    },
  ]);

module.exports = withPodDeploymentTarget;
module.exports.patchPodfile = patchPodfile;
```

Register it in `app.json` (or `app.config.*`):

```json
"plugins": [
  "./plugins/with-ios-pod-deployment-target"
]
```

How it behaves:

- The floor is the same Ruby expression as the Podfile's `platform :ios, ...` line, so it cannot drift from the app's deployment target.
- It only raises targets that are below the floor. Pods that declare a newer target keep it.
- It throws if the Podfile template ever stops matching, instead of silently doing nothing.
- Do not work around this by passing `IPHONEOS_DEPLOYMENT_TARGET=15.1` to `xcodebuild`. A command-line override also lowers pods that need a newer target and creates availability errors there.

Verify:

```sh
npx expo prebuild -p ios --clean
grep -n "with-ios-pod-deployment-target" ios/Podfile
grep -o "IPHONEOS_DEPLOYMENT_TARGET = [0-9.]*" ios/Pods/Pods.xcodeproj/project.pbxproj | sort | uniq -c
```

The last command should list nothing below the platform version (the template default is 15.1 on SDK 54 and 16.4 on SDK 56).

## Fix 2: adopt the UIKit scene life cycle

### Expo SDK 57.0.23 and newer

Use Expo's built-in support and do not add the plugin below:

```json
["expo-build-properties", { "ios": { "enableSceneSupport": true } }]
```

- It throws if the installed `expo` is below 57.0.23.
- It throws if the app already declares `UIApplicationSceneManifest`, so remove the custom plugin first when switching to it.
- On SDK 58 and newer the property is a no-op with a warning; remove it.

### Expo SDK 53 to 56 (and 57.0.0 to 57.0.22)

Create `plugins/with-ios-scene-lifecycle.js`:

```js
const { withAppDelegate, withInfoPlist } = require('@expo/config-plugins');

/**
 * Adopts the UIKit scene life cycle, which the iOS 27 SDK requires: without it the app is killed at
 * launch in `_UIApplicationEvaluateRuntimeIssueForNoSceneLifecycleAdoption`.
 *
 * Declaring the manifest alone is NOT enough, and fails deceptively - the process survives and
 * renders black, because the window `AppDelegate` builds with `UIWindow(frame:)` is never attached
 * to the `UIWindowScene`. The window has to be created FROM the scene, which moves React Native's
 * startup into the scene delegate.
 *
 * Expo ships this natively from SDK 57.0.23 (`ExpoAppSceneDelegate`, enabled through
 * expo-build-properties `ios.enableSceneSupport`) and in the project template from SDK 58. Earlier
 * SDKs have nothing, so the same shape lives here in app code. Remove this plugin when upgrading.
 */

const MARKER = '// ios-scene-lifecycle';

// The window and the startReactNative call are matched separately: other plugins inject their own
// lines between them, and that code still has to run at didFinishLaunching time.
const WINDOW_RE = /^[ \t]*window = UIWindow\(frame: UIScreen\.main\.bounds\)\r?\n/m;
const START_RN_RE = /^[ \t]*factory\.startReactNative\(\r?\n[ \t]*withModuleName: "main",\r?\n[\s\S]*?launchOptions: launchOptions\)\r?\n/m;
const WINDOW_PROP = '  var window: UIWindow?\n';

// The scene delegate forwards links to AppDelegate's own overrides rather than to RCTLinkingManager,
// so Expo's subscribers (expo-linking, expo-router) still see them. That is only correct while those
// overrides notify RCTLinkingManager themselves - asserted here, because a silent change would mean
// deep links reach native and never reach JS.
const LINKING_OPEN = 'RCTLinkingManager.application(app, open: url, options: options)';
const LINKING_CONTINUE = 'RCTLinkingManager.application(application, continue: userActivity, restorationHandler: restorationHandler)';

const SCENE_DELEGATE = `
${MARKER}
@objc(SceneDelegate)
class SceneDelegate: UIResponder, UIWindowSceneDelegate {
  var window: UIWindow?

  private var appDelegate: AppDelegate? {
    UIApplication.shared.delegate as? AppDelegate
  }

  func scene(
    _ scene: UIScene,
    willConnectTo session: UISceneSession,
    options connectionOptions: UIScene.ConnectionOptions
  ) {
    // Trapping rather than returning: a silent return here is the black screen this plugin exists
    // to prevent, and it would look like a JS failure rather than a native one.
    guard let windowScene = scene as? UIWindowScene,
          let appDelegate,
          let factory = appDelegate.reactNativeFactory else {
      fatalError("SceneDelegate: no UIWindowScene, or AppDelegate had no React Native factory yet.")
    }

    let window = UIWindow(windowScene: windowScene)
    self.window = window
    // Code reading \`UIApplication.shared.delegate?.window\` predates scenes and still expects it set.
    appDelegate.window = window

    let browsingWebActivity = connectionOptions.userActivities.first {
      $0.activityType == NSUserActivityTypeBrowsingWeb
    }

    factory.startReactNative(
      withModuleName: "main",
      in: window,
      launchOptions: Self.launchOptions(
        from: appDelegate.launchOptions,
        url: connectionOptions.urlContexts.first?.url,
        userActivity: browsingWebActivity))

    // A cold-start link arrives here, never in application(_:open:options:).
    connectionOptions.urlContexts.forEach { open($0) }
    connectionOptions.userActivities.forEach { continueActivity($0) }
  }

  func scene(_ scene: UIScene, openURLContexts URLContexts: Set<UIOpenURLContext>) {
    URLContexts.forEach { open($0) }
  }

  // Handoff progress callbacks and quick actions are not forwarded. Add them here if the app uses
  // them.
  func scene(_ scene: UIScene, continue userActivity: NSUserActivity) {
    continueActivity(userActivity)
  }

  func sceneDidBecomeActive(_ scene: UIScene) {
    appDelegate?.applicationDidBecomeActive(UIApplication.shared)
  }

  func sceneWillResignActive(_ scene: UIScene) {
    appDelegate?.applicationWillResignActive(UIApplication.shared)
  }

  func sceneWillEnterForeground(_ scene: UIScene) {
    appDelegate?.applicationWillEnterForeground(UIApplication.shared)
  }

  func sceneDidEnterBackground(_ scene: UIScene) {
    appDelegate?.applicationDidEnterBackground(UIApplication.shared)
  }

  func sceneDidDisconnect(_ scene: UIScene) {
    window = nil
  }

  private func open(_ context: UIOpenURLContext) {
    var options: [UIApplication.OpenURLOptionsKey: Any] = [.openInPlace: context.options.openInPlace]
    if let sourceApplication = context.options.sourceApplication {
      options[.sourceApplication] = sourceApplication
    }
    if let annotation = context.options.annotation {
      options[.annotation] = annotation
    }
    _ = appDelegate?.application(UIApplication.shared, open: context.url, options: options)
  }

  private func continueActivity(_ userActivity: NSUserActivity) {
    _ = appDelegate?.application(
      UIApplication.shared,
      continue: userActivity,
      restorationHandler: { _ in })
  }

  /// Rebuilds the launch options \`Linking.getInitialURL()\` reads. Under the scene life cycle a
  /// cold-start URL arrives in \`connectionOptions\` instead, and the \`url\` event routed above fires
  /// before JS is listening - so without this a link that launches the app reaches no one.
  ///
  /// Keys are spelled out rather than taken from the deprecated \`UIApplication\` accessors, because
  /// React Native reads the dictionary by these exact strings.
  private static func launchOptions(
    from base: [UIApplication.LaunchOptionsKey: Any]?,
    url: URL?,
    userActivity: NSUserActivity?
  ) -> [UIApplication.LaunchOptionsKey: Any]? {
    var options = base ?? [:]
    if let url {
      options[UIApplication.LaunchOptionsKey(rawValue: "UIApplicationLaunchOptionsURLKey")] = url
    }
    if let userActivity {
      options[UIApplication.LaunchOptionsKey(rawValue: "UIApplicationLaunchOptionsUserActivityDictionaryKey")] = [
        "UIApplicationLaunchOptionsUserActivityTypeKey": userActivity.activityType,
        "UIApplicationLaunchOptionsUserActivityKey": userActivity
      ]
    }
    return options.isEmpty ? nil : options
  }
}
`;

const NEW_WINDOW_LINE = `    // The window is created by SceneDelegate: under the scene life cycle it must come from the
    // UIWindowScene, so only the launch options are kept here for it to read back.
    self.launchOptions = launchOptions
`;

function patchAppDelegate(contents) {
  if (contents.includes(MARKER)) return contents;

  const required = [
    [WINDOW_RE, 'the window creation line'],
    [START_RN_RE, 'the factory.startReactNative call'],
    [LINKING_OPEN, "AppDelegate's RCTLinkingManager open-URL call"],
    [LINKING_CONTINUE, "AppDelegate's RCTLinkingManager continue-userActivity call"],
  ];
  for (const [needle, what] of required) {
    const found = needle instanceof RegExp ? needle.test(contents) : contents.includes(needle);
    if (!found) {
      throw new Error(
        `with-ios-scene-lifecycle: AppDelegate.swift no longer contains ${what}. The Expo template ` +
          'changed; re-check this plugin against it rather than loosening the match.'
      );
    }
  }
  if (!contents.includes(WINDOW_PROP)) {
    throw new Error("with-ios-scene-lifecycle: could not find AppDelegate's window property.");
  }

  return (
    contents
      .replace(WINDOW_RE, NEW_WINDOW_LINE)
      .replace(START_RN_RE, '')
      .replace(WINDOW_PROP, `${WINDOW_PROP}  var launchOptions: [UIApplication.LaunchOptionsKey: Any]?\n`) +
    SCENE_DELEGATE
  );
}

const withSceneAppDelegate = (config) =>
  withAppDelegate(config, (cfg) => {
    if (cfg.modResults.language !== 'swift') {
      throw new Error(`with-ios-scene-lifecycle: expected a Swift AppDelegate, got ${cfg.modResults.language}.`);
    }
    cfg.modResults.contents = patchAppDelegate(cfg.modResults.contents);
    return cfg;
  });

// SceneDelegate is appended to AppDelegate.swift rather than added as its own file, so no pbxproj
// surgery is needed: it lands in the same module, which is what PRODUCT_MODULE_NAME resolves to.
const withSceneManifest = (config) =>
  withInfoPlist(config, (cfg) => {
    cfg.modResults.UIApplicationSceneManifest = {
      UIApplicationSupportsMultipleScenes: false,
      UISceneConfigurations: {
        UIWindowSceneSessionRoleApplication: [
          {
            UISceneConfigurationName: 'Default Configuration',
            UISceneDelegateClassName: '$(PRODUCT_MODULE_NAME).SceneDelegate',
          },
        ],
      },
    };
    return cfg;
  });

module.exports = (config) => withSceneManifest(withSceneAppDelegate(config));
module.exports.patchAppDelegate = patchAppDelegate;
```

Register it in `app.json`:

```json
"plugins": [
  "./plugins/with-ios-scene-lifecycle"
]
```

What it does:

1. Adds `UIApplicationSceneManifest` to `Info.plist`, pointing at a `SceneDelegate` class.
2. Moves window creation and `factory.startReactNative` out of `AppDelegate` and into that `SceneDelegate`, which is appended to `AppDelegate.swift`. Appending keeps it in the same module, so no `project.pbxproj` edit is needed.
3. Forwards URLs and user activities to AppDelegate's own overrides, so expo-linking and expo-router still receive deep links. It rebuilds the launch options so `Linking.getInitialURL()` still sees a cold-start link.
4. Forwards active, inactive, foreground and background events to AppDelegate, so Expo app-delegate subscribers and `AppState` keep working.

Traps this plugin exists to avoid:

- **Declaring the scene manifest alone is not enough.** The process survives but renders black, because the window AppDelegate builds with `UIWindow(frame:)` is never attached to the `UIWindowScene`. The window has to be created from the scene.
- **Do not call `RCTLinkingManager` directly from the scene delegate.** expo-router reads a registry that only expo-linking's app-delegate subscriber fills, so a direct call loses every cold-start deep link.
- **A cold-start link arrives in `connectionOptions`,** never in `application(_:open:options:)`. The `url` event fires before JS is listening, which is why the launch options are rebuilt.
- **Code that reads `UIApplication.shared.delegate?.window`** predates scenes and still works, because the plugin sets `appDelegate.window`.
- **Handoff progress callbacks and quick actions are not forwarded.** Add them to `SceneDelegate` if the app uses them.
- **The plugin throws when the AppDelegate template does not match.** Re-check it against the new template rather than loosening the match. It has been checked against the SDK 54 and SDK 56 templates.

Verify:

```sh
npx expo prebuild -p ios --clean
/usr/libexec/PlistBuddy -c "Print :UIApplicationSceneManifest" ios/<AppName>/Info.plist
grep -n "class SceneDelegate" ios/<AppName>/AppDelegate.swift
```

Then on an iOS 27 simulator:

- [ ] The app launches and renders: no crash, no black screen.
- [ ] Custom-scheme deep link from a cold start: kill the app, then `xcrun simctl openurl booted "<scheme>://<path>"`.
- [ ] Custom-scheme deep link while the app is running.
- [ ] Universal link from a cold start, if the app has associated domains.
- [ ] `AppState` changes fire on background and foreground (for example, lock-screen or auto-lock logic).
- [ ] Anything that presents native UI from the key window still works (camera, document picker, KYC or payment SDKs, biometric prompts).

Remove the plugin when moving to SDK 57.0.23+ (switch to `ios.enableSceneSupport`) or SDK 58+.

## Fix 3: update to the newest patch of your SDK line

```sh
npm view expo@<SDK> version          # lists the patch releases; take the newest
npm install expo@~<SDK>.0.<latest>
npx expo install --fix               # aligns the other expo-* packages to that patch
```

Known cases:

- **SDK 56:** `expo-modules-jsi` below 56.0.13 fails to compile, because Swift refuses to form a C function pointer inside a ternary. `expo-modules-core` accepts `~56.0.10`, so an old lockfile can keep the broken version. Check with `npm ls expo-modules-jsi`, and run `npm update expo-modules-jsi` if needed.
- **SDK 54:** the newest patch on 2026-10-30 is `expo` 54.0.38, with `expo-modules-core` 3.0.30, which contains Swift source fixes (fully qualified `#selector` references). A full Xcode 27 build on SDK 54 has not been verified yet; see the status table.

If a native library outside Expo fails to compile, check for a newer patch release of that library before patching it.

## If you upgrade the SDK instead

An SDK upgrade also fixes fix 2 (SDK 57.0.23+), but it brings unrelated breakage, so treat it as its own project with a full QA cycle rather than as the iOS 27 fix. One example: SDK 57 moves Android to Gradle 9, which removes `jcenter()`, and any library that still calls it fails the Android build. If you patch such a library with patch-package, pin it to the exact version the patch was made for. A caret range with no committed lockfile lets a fresh install resolve a version the patch does not apply to, and the install fails when `CI` is set.

## Rollback

Remove the plugin from `plugins` in `app.json`, delete the plugin file, and run `npx expo prebuild -p ios --clean`.
